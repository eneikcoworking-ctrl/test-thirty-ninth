# Model Card: OpenAI LLM for Offer Personalization

## Model Details
- **Architecture**: LLM via REST API (e.g., gpt-3.5-turbo).
- **Use Case**: Personalize cold outreach base offers using extracted lead metadata (Lead bio).
- **Integration**: `OpenAiLlmClient` managed by `LlmOfferPersonalizationService`.

## Data Lineage
- **Training Data**: Pre-trained on public internet data (OpenAI base models). Not fine-tuned on proprietary lists.
- **Input Data (Inference)**: `baseOffer` (internal template) + `lead.metadata` (public bio).

## Epistemic Status & Validation Criteria
According to BARCAN-TAG-04 Role Charter, every behavior output must be classified as VERIFIED, INFERRED, or ASSUMED.

- **Generative Output Status: ASSUMED**
  The actual text generated by the LLM is nondeterministic and cannot be proven logically true or functionally "safe" in all cases just by reading it. Its tone and coherence are ASSUMED based on the strict prompt instructions.

- **Fallback Behavior Status: VERIFIED**
  The fallback to the deterministic `baseOffer` is VERIFIED. The service enforces strict bounds:
  - If output length > 300 characters, it falls back to base offer.
  - If output contains standard AI refusal phrases (e.g., "as an AI"), it falls back to base offer.
  - If the API throws an exception or returns empty, it falls back to base offer.
  - If the Lead has no metadata, it falls back to base offer.

This ensures that the pipeline never blocks or fails open; the user is guaranteed to receive at least the original base offer.
